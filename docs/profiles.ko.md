# 상황판 "프로필·에이전트" 화면

WinForms 프로필 스위처가 하던 일을 상황판 안에서 하는 화면입니다. 메인 에이전트 4명(Sisyphus, Hephaestus, Prometheus, Atlas)의 레인과 핀도 여기서 바꿉니다.

관련 문서: [mirror-source.md](mirror-source.md), [refresh-decision.md](refresh-decision.md)

---

## 화면 둘러보기

### 카드 1. 화면 열기

**할 일:** 실시간 상황판 왼쪽 레일에서 "프로필·에이전트"를 누릅니다.
**결과:** 아래 구역이 차례로 보입니다.

- **메인 에이전트:** 에이전트별 레인, 핀, 기억
- **프로필:** 기본 6개 프로필, 내가 만든 프로필, 현재 선택
- **역할 배치:** 에이전트·카테고리별 서비스, 모델, 추론
- 메인 모델, 모델 레인, 요약 모델, 메모리 행, 추천 안내, 구독 목록
- **바꿀 값:** 고친 내용이 모이는 곳과 미리보기·적용 단추

파일로 연 상황판에서는 "보기 전용" 안내만 나오고 단추가 없습니다. 바꾸는 일은 실시간 상황판에서만 됩니다. 설치된 omo 번들이 화면이 아는 버전과 다르면 "인벤토리 갱신 필요"가 뜨고 역시 보기 전용이 됩니다.

### 카드 2. 미리보기

**할 일:** 값을 고친 뒤 **미리보기**를 누릅니다.
**결과:** 파일별 바뀔 내용이 보입니다. 미리보기는 아무 파일도 쓰지 않습니다.

### 카드 3. 적용

**할 일:** **적용**을 누릅니다.
**결과:** "적용했어요"가 뜨고, 백업 경로와 새 해시가 함께 나옵니다. 파일을 쓰는 것은 적용뿐입니다. 쓰기 전에 백업을 먼저 만들고, 다시 읽어서 검증하다 실패하면 백업으로 되돌립니다.

### 카드 4. 409(충돌)가 뜰 때

**뜻:** 화면을 연 뒤에 다른 곳(WinForms 앱, 다른 창, 손 편집)에서 대상 파일이 바뀌었다는 뜻입니다. 주석이 들어간 설정 파일, 없는 설정 파일, 낡은 인벤토리도 409로 거절됩니다.
**할 일:** 고친 값은 남아 있으니 새로고침한 뒤 다시 적용합니다.
**결과:** 아무 파일도 쓰이지 않은 채로 멈춰 있다가, 새로 읽은 상태 위에서 다시 적용됩니다.

## 카드 글과 새 프로필

### 카드 4-1. 카드 글 편집

**할 일:** 카드의 **편집**을 눌러 이름(40자)·꼬리표(24자)·설명(160자)을 고친 뒤 **저장**을 누릅니다. 기본 프로필은 **기본 글로**로 원래 글에 돌아갑니다.
**결과:** 카드 글만 바뀝니다. 프로필 선택과 적용 상태는 그대로이고, 쓰는 파일은 `runtime/native-profile-switcher-profile-cards.json` 하나입니다.

### 카드 4-2. 새 프로필 만들기

**할 일:** 카드 목록 아래 **새 프로필**을 누르고 이름(필수)·꼬리표·설명과 복제할 프로필을 고른 뒤 **만들기**를 누릅니다.
**결과:** 고른 프로필의 역할·모델 배치를 그대로 가진 프로필이 생기고(`custom-n`, 설정 이름 `native-custom-n`), 그 카드가 보기 대상이 됩니다. 만들기만 하고 적용하지 않으므로 "적용 중" 표시는 원래 카드에 남습니다. 쓰려면 새 카드의 **적용**을 누릅니다.

- CommandCode 구독 배정은 프로필 이름에 묶여 있어 새 프로필로 복사되지 않습니다.
- 삭제와 순서 바꾸기는 없습니다. 지우려면 아래 되돌리기를 씁니다.
- 개수 상한은 없습니다. 배치는 사용자 프로필 12개(카드 18장)까지 390·1440 폭에서 확인했습니다.
- 사용자 프로필에는 숫자 단축키가 없습니다.
- 카드 글을 저장하거나 프로필을 만들 때마다 백업 파일이 하나씩 쌓입니다.

### 카드 4-3. WinForms 스위처와 함께 쓸 때

WinForms 스위처는 기본 6개 프로필의 카드만 만듭니다. 상황판에서 만든 프로필을 적용한 뒤 WinForms 앱을 열면 어느 카드도 선택되지 않은 채로 시작합니다(앱 소스를 읽고 내린 결론이며 앱을 실제로 실행해 보지는 않았습니다). 내가 만든 프로필은 WinForms 앱에서 고르거나 고칠 수 없으니 상황판에서만 다루십시오.

## 백업과 복원

### 카드 5. 백업 찾기

**위치:** `<primaryHome>/runtime/native-profile-switcher-backups/` (보통 `C:/Users/USER/.omo/runtime/native-profile-switcher-backups/`)
**결과:** 적용할 때마다 바뀌는 파일의 이전 내용이 여기에 남습니다.

### 카드 6. 손으로 되돌리기

**할 일:** 되돌릴 파일의 백업을 원래 자리에 복사합니다. 상황판과 WinForms 앱은 닫아 둡니다.
**결과:** 다음에 화면을 열면 되돌린 값이 보입니다. 화면이 열려 있었다면 다음 적용은 409로 거절되니 새로고침하세요.

새 프로필 만들기를 되돌릴 때는 같은 시각이 붙은 백업을 **모두 함께** 되돌립니다: `profile-cards-<시각>.json`(카드 파일), `omo-<시각>.jsonc`(각 홈의 설정), 메인 곁 파일과 역할 백업 파일의 백업. 카드 파일을 먼저, 설정 파일을 그다음에 되돌립니다. 첫 카드 저장 전에는 카드 파일이 없었으므로 백업 대신 그 파일을 지우면 됩니다.

## 명령줄(CLI)

WinForms의 `-PrintStatus`, `-DumpState`, `-Apply`, `-ApplyIntentPath`, `-DryRun`에 해당합니다. 화면과 같은 검사를 거칩니다. 홈 경로는 기본값이 없으니 꼭 넘깁니다.

### 카드 7. 상태 보기

```
node scripts/profiles-cli.mjs status --primary-home <dir> --stable-home <dir>
```

**결과:** 현재 프로필, 메인 모델, 대상 파일 해시가 JSON으로 나옵니다. `dump`를 쓰면 화면이 받는 전체 상태가 나옵니다.

### 카드 8. 미리보기와 적용

```
node scripts/profiles-cli.mjs apply <intent.json> --dry-run --primary-home <dir> --stable-home <dir>
```

**결과:** `--dry-run`이면 미리보기만 하고 아무것도 쓰지 않습니다. `--dry-run`을 빼면 적용합니다. intent 파일은 `{"changes": [...]}` 꼴이고, `expected`와 `rosterRevision`을 빼면 지금 상태 값을 씁니다.

홈 인자가 빠지면 종료 코드 2와 함께 `--primary-home and --stable-home are required`를 출력합니다.
