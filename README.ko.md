# OMO 상황판 사용 안내

대화 여러 개의 상태를 브라우저 한 장으로 보고, 상황판에서 바로 또는 아무 창에서 한 줄로 결정합니다. 비유: 대화마다 긴 편지를 읽는 대신, 게시판 한 장을 훑는 것.

## 1. 열기
1. 아무 OMO 대화창에서 `/brief` 를 칩니다.
2. 채팅에 `상황판(실시간): <주소>` 가 뜨고, 그 주소가 브라우저에 열립니다.
3. 실시간 서버가 없으면 채팅에 `상황판: <경로>` 가 뜨고 파일로 열립니다.
4. 경로만 보고 싶으면 `/brief path` 를 칩니다.

실시간 주소 (기본):
```
http://127.0.0.1:47317/
```
- 이 주소는 이 PC 안에서만 열립니다 (127.0.0.1).
- 47317 이 쓰이는 중이면 47318 ... 47326 순서로 밀립니다.
- 실제 주소는 서버가 채팅에 적어 줍니다. 파일로는 `server.json` 에 적힙니다.

파일 상황판 (서버 없이):
```
C:/Users/USER/.omo-stable-500/home/.omo/agent/briefing/state/index.html
```
- 같은 상황판이고, 화면에 보이는 동안 2~3초마다 저절로 새 내용을 반영합니다 (서버가 없어도 계속됩니다).
- 다만 화면을 보고 있을 때만 갱신합니다. 다른 탭에 가려지면 멈춥니다.
- 실시간 주소와 파일 주소는 브라우저 저장소가 따로입니다. 소리 설정과 '본 항목' 도 각각 따로 기억됩니다.

## 2. 화면 구성
- 왼쪽 끝 레일, 그 옆 사이드바, 오른쪽 본문 위의 탭, 대화 페이지 안의 다섯 하위 탭(개요 / 계획 / 작업자 / 결정 / 보고서)으로 나뉩니다.
- 새 내용은 실시간 주소에서 1~2초, 파일에서는 보이는 동안 2~3초마다 반영됩니다. 보던 탭과 읽던 자리는 그대로입니다.
- 글자를 고르거나 입력 중이면 잠깐 미루고 `● 새 내용 - 선택·입력이 끝나면 반영` 배지를 띄웁니다. 연결이 끊기면 저절로 다시 붙습니다.

| 레일 버튼 | 하는 일 |
| --- | --- |
| 홈 | 나를 기다림 / 진행 중 / 끝남 묶음으로 전체를 봄 |
| 대화 | 열린 탭, 최근, 이전 대화 목록. 누르면 그 대화 페이지가 탭으로 열림 |
| 수신함 | 답을 기다리는 결정과 질문만 모아 봄 |
| 계획 | 계획이 있는 대화만 봄 |
| 닫힌 창 | 끝나서 닫힌 대화를 검색 |
| 설정 | 🔔 소리, ℹ 표시 뜻 |

- 사이드바 닫기: 위의 « 또는 Ctrl+\\. 다시 열기: 탭 줄 왼쪽의 » 또는 Ctrl+\\. 가장자리를 끌면 너비가 바뀝니다.
- 상황판이 너무 커지면 오래된 대화의 자세한 정보(할 일 목록, 자료 등)부터 줄이고, 위에 `오래된 대화 n개는 자세한 정보를 줄였어요` 한 줄을 띄웁니다. 파일 경로는 절대 줄여 쓰지 않습니다. 통째로 보이거나 아예 빠집니다.

| 칩 | 뜻 |
| --- | --- |
| 증거 있음 | 적어 둔 파일이 그때 내용 그대로 있음 (다시 실행해 본 건 아님) |
| 증거 바뀜 / 증거 사라짐 | 그 파일이 바뀌었거나 없어짐 |
| 보고만 됨 | 에이전트가 말만 함 |
| 미확인 | 확인한 사람도 증거도 없음 |
| 후보 / 실사용 적용 / 적용 해당 없음 | 실사용에 안 올림 / 올렸다고 기록함 / 올릴 게 없는 일 |
| 보고 없음 | 그 대화가 일은 했는데, 끝내면서 상황판 보고를 안 남김 |
| 오래됨 | 마지막 갱신(⏱)이 오래전 |

## 3. 주석 보내기
- 고르는 법 세 가지: 블록에 마우스를 올려 `주석 달기`, 글자를 끌어 고르기, 빈 공간에서 상자를 끌어 여러 블록 고르기(블록 위에서 시작하려면 Alt+드래그).
- 의견을 쓰고 ✏️ 고쳐줘 / ❓ 질문 을 고른 뒤 `주석 추가` (Ctrl+Enter). 주석은 아래 트레이에 쌓이고 한 번에 10개까지입니다. 트레이의 보내기를 누르면 그 대화 채팅에 `[상황판 피드백]` 메시지로 갑니다. 고른 글, 위치, 의견, 관련 파일이 번호대로 묶여 있고, 채팅에 직접 친 말과 같습니다. 주석 뒤 블록이 바뀌면 `바뀜·사라짐` 이 붙습니다. 그때 적어 둔 내용 그대로 보내집니다.
- 파일로 연 페이지에서는 `Markdown 복사` 로 복사해 그 대화창에 붙여넣습니다.

## 4. 소리 켜기·끄기
- 레일의 설정을 열고 종 아이콘(bell) 소리 켜짐 / 빗금 친 종 아이콘(bell-off) 꺼짐 버튼 하나로 켜고 끕니다.
- 소리는 페이지를 한 번 눌러야 켜집니다 (브라우저 규칙). 안내가 뜨면 화면을 한 번 누르세요.
- 새로 답을 기다리는 항목이 생기면 빨간 띠 + 짧은 소리 1회, 탭 제목 앞에 (N) 이 붙습니다.
- 처음 페이지를 열 때 이미 있던 항목은 띠만 보이고 소리는 나지 않습니다.
- 답하거나 닫으면 띠에서 빠지고 같은 항목으로 다시 울리지 않습니다.

## 5. 보고서
- 대화 페이지의 보고서 탭에 에이전트가 올린 그림 시안이 모입니다. 그림을 누르면 그 위치에 핀 주석을 달며, 그림을 확대하지 않습니다. 결정과 이어진 그림에는 `이걸로 고르기` 가 있습니다. 누르면 그 선택지로 답하는 확인 줄이 뜹니다. 그림에 단 주석은 그림 위 번호 핀으로 보입니다.

## 6. 작업자와 계획
- 대화 페이지의 작업자 탭: 이름, [모델], 상태 점(맥박 진행, ✔ 끝, ✖ 오류, 회색 취소), ⏱ 경과, 지금 하는 일. 줄을 펼치면 할 일이 ✔ / ● / ○ 로 보입니다.
- 10분 넘게 소식이 없으면 '응답 없음 10분', 알림 전이면 '정보 대기' 입니다. 계획 탭: 🎯 목표, 단계 흐름, 할 일 표, 질의응답 표, ✔ 성공하면, 🚫 안 하는 것. 앞 단계가 멈추면 '막힘' 이 붙습니다. 칩: `계획 요약 없음`, `계획 파일이 요약 뒤에 바뀜`, `요약에 없는 할 일 n개`. 다른 대화가 실행 중이면 이동 링크가 보입니다.

## 7. 답하는 법
1. 선택지: 결정의 `A · <선택지>` 를 누르고 확인 줄 `🗂 수리 #181 대화에 B를 보낼까요?` 에서 [보내기]. `보내는 중…` 뒤 전달 표시로 바뀝니다. 보낸 답은 못 바꿉니다.
2. 답글: `✍ 답글` 로 500자까지 씁니다. 채팅에 직접 친 말과 같습니다 (승인도 포함).
3. 터미널: 아무 대화창에서 `/decide 12A 13B`. 번호만 쓰면 추천안 (`/decide 12`). `반영: #12 A, #13 B` 가 보이면 성공. 틀린 번호가 섞이면 **아무것도 적용 안 됩니다**.
4. 보류: [보류] 를 누르면 에이전트에 `[결정 보류]` 가 가고, 다시 묻거나 추천안으로 진행하지 않습니다. 보류됨 묶음의 [다시 열기] 로 되돌립니다.
5. 같은 질문이 터미널에도 열려 있으면(board_question) 상황판이나 터미널 중 한 곳에서 한 번만 답하면 둘 다 닫힙니다.
6. `답할 창: 🗂 수리 #181` 이 보이면 그 창에서만 답합니다. [그 창으로 이동] 으로 엽니다.

| 표시 | 뜻 |
| --- | --- |
| 대기: 작업이 끝나면 전달 | 그 대화가 일하는 중, 끝나면 받음 |
| 대기: 그 대화가 다시 열리면 전달 | 그 대화가 닫혀 있음 |
| 전달 중 | 보냈고 확인 기다림 |
| 전달됨 ⏱ | 그 대화가 받음 (시각 표시) |

## 8. 끄기와 제거
- 일시 끄기: `/brief off` → `브리핑 꺼짐: ...` 이 보입니다.
- 다시 켜기: `/brief on` → `브리핑 켜짐: ...` 이 보입니다.
- 완전 제거:
```
node C:/Users/USER/orca/projects/piomo-briefing/scripts/install.mjs --agent-dir C:/Users/USER/.omo-stable-500/home/.omo/agent --uninstall
```
`removed ... (generations and state kept)` 가 보이면 끝. 이 파일 하나를 지워도 됩니다:
```
C:/Users/USER/.omo-stable-500/home/.omo/agent/extensions/omo-briefing.js
```
먼저 확인만 하려면 끝에 `--dry-run` 을 붙이세요 (아무것도 안 씀).

## 9. 문제 해결

| 증상 | 뜻 | 할 일 |
| --- | --- | --- |
| `적용 안 함: ...` | 번호가 틀렸거나 이미 답함 | 카드 번호 다시 보고 다시 치기 |
| `파일 권한 오류 - 다시 시도` | 다른 창과 동시에 씀 | 같은 명령 한 번 더 |
| 대화가 안 보임 | 설치 전에 열려 있던 대화 | 그 대화를 새로 열기 |
| 소리가 안 남 | 브라우저가 아직 소리를 허용하지 않음 | 화면을 한 번 클릭하고 🔔 확인 |
| 움직임·깜빡임이 안 보임 | Windows '애니메이션 효과' 가 꺼져 있음 | 설정 > 접근성 > 시각 효과 > 애니메이션 효과 켜기 |
| 실시간 갱신이 안 됨 | 서버가 없거나 이 탭이 잠들었음 | 새 대화에서 `/brief` 로 주소 다시 열기 |
| 포트가 다름 | 47317 이 쓰이는 중이라 밀렸음 | 채팅에 적힌 주소를 쓰면 됨 |
| 이미 답했거나 닫힌 결정 | 먼저 답했거나 결정이 닫힘 | 카드의 전달 표시 보기 |
| 이 대화는 답글을 못 받아요 | 예전부터 열린 대화 | 선택지로 답하기 |
| 상황판을 다시 열어 주세요 | 서버가 바뀜 (한 번은 저절로 새로 고침) | `/brief` 로 주소 다시 열기 |
| 상황판이 꺼져 있어요 | `/brief off` 상태 | `/brief on` |
| 보내지 못했어요 / 이동 실패 | 연결이 끊겼거나 herdr 가 탭을 못 엶 | 다시 누르기, 또는 herdr 에서 직접 열기 |
| 이 대화는 아직 주석을 못 받아요 | 예전부터 열린 대화 | 대화를 재시작하거나, Markdown 복사 후 붙여넣기 |
| 너무 길어요 - 주석을 나눠 보내세요 | 한 번에 보내기엔 김 | 몇 개만 먼저 보내기 |
| 바뀜·사라짐 | 주석 뒤 블록이 바뀜 | 그대로 보내도 됨 (적어 둔 내용이 감) |
| 터미널에서 답하세요 | 상황판이 닫을 수 없는 내장 질문 | 그 창의 터미널에서 답하기 |

## 10. 알아둘 것
- 설치 전에 조용한 PC에서 `npm run check:timing`을 한 번 돌린다.
- 열려 있던 대화는 재시작할 때까지 예전 세대로 동작함. 최신 상황판은 대화 하나를 재시작하면 열림. 막히면 `/brief off` 후 `/brief on`.
- 크롬 설정 > 성능 > '항상 활성 상태로 유지' 에 이 주소를 추가하면 백그라운드 탭에서도 소리와 갱신이 이어집니다.
- 이 PC 의 크롬은 Windows '애니메이션 효과' 가 꺼져 있으면 prefers-reduced-motion: reduce 로 봅니다. 그래서 맥박·이동·번쩍임이 안 보입니다. 켜면 보입니다.
- 선택지 답(A/B/C)은 계획 선택일 뿐 설치·푸시·삭제 승인이 아닙니다. 답글은 채팅에 직접 친 말과 같습니다. 상황판 답하기는 실시간 주소(http://127.0.0.1:...)에서만 됩니다. 파일로 연 상황판은 보기 전용입니다.
